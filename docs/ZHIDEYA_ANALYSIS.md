# 职得鸭（AI 求职管家）深度解析

> 说明：职得鸭（C 端 AI 求职管家）公开技术细节极少。其招聘端孪生品「世纪云猎」（AI 招聘官）披露最完整，且二者共用同一套 Agent 框架，本文以其为反推主要依据。标注【确认】= 官网/报道明确；【推断】= 基于行业常识与孪生品合理推测。

## 一、产品与公司定位
- 【确认】出品方：上海世纪云端人工智能科技有限公司（张江，上海人工智能行业协会会员，入驻「模力社区」）。
- 【确认】定位：C 端「AI 求职管家」—— 智能匹配 + 文案撰写 + 自动投递 + 跟进，全程 AI 托管，求职者「只需准备面试」。
- 【确认】孪生关系：B 端「世纪云猎」是同一 Agent 框架的镜像（"招聘界的贾维斯"），7×24 全功率模仿 HR 操作：主动搜人才、打招呼、自动聊天初筛、记录手机号、交换微信。

## 二、技术栈推断
- 【确认】形态：云原生 SaaS / 多租户，Web 后台（可能配小程序），非本地客户端。与我们的"本地 + CDP"是根本差异——用户不设环境，厂商统一托管运行实例。
- 【确认】大模型能力：世纪云端是"大模型应用"公司，明确提供「行业大模型微调与定制」「私有化 AI 知识库部署」「业务场景 AI Agent 开发」。
- 【推断】LLM 层：通用大模型 API（或自研/微调模型）+ 招聘行业知识库（JD 解析、话术模板、匹配规则）。
- 【推断】Agent 框架：多 Agent 协作（需求理解 / 寻访 / 沟通 / 投递管理），典型 LLM Agent + 工具调用（function calling）模式，带状态与记忆。
- 【推断·关键】多平台适配层，如何接 BOSS/猎聘/51job/智联？两路并存：
  1) 官方开放平台 API：BOSS直聘有开放平台（open.bosszhipin.com）面向 ATS/第三方集成，猎聘也有开放接口。这是"无缝对接、不弹验证码"最可能的解释。
  2) 云端浏览器/设备指纹池：无 API 的平台走云端托管浏览器自动化（类 Playwright/CDP），固定 IP + 养熟设备指纹 + 拟人节奏规避风控。
- 【确认】数据底座：简历库、岗位库、候选人画像、匹配度评分、投递漏斗（世纪云猎原文明确"招聘漏斗、渠道效果、人才画像一目了然"）。

## 三、UI 界面
- 【确认】单一 Web 后台，统一看板管理所有渠道（世纪云猎："在一个后台管理所有渠道的候选人"）。
- 【推断】模块：求职者画像/意向设置、岗位推荐流、简历与多版本管理、投递看板（状态/漏斗）、AI 沟通/跟进记录、数据洞察。
- 【推断】交互：对话式（"AI 交流"）+ 看板式，弱化配置、强调"开箱即用、托管"。

## 四、投递逻辑（核心）
反推自世纪云猎的链路：
1. 需求理解 Agent：解析简历 + 求职意向 → 生成"求职画像"。
2. 寻访 Agent：跨平台并行搜岗，按画像语义匹配（非关键词堆砌），多维度打分。
3. 投递 Agent：对达标岗位自动生成针对性话术/简历，发起投递（BOSS 打招呼、51job/智联一键投等）。
4. 沟通 Agent：7×24 AI 初聊、意向初筛、自动复聊唤醒、记录关键信息，并跟进。
5. 数据层：状态追踪 + 漏斗分析，决策权留给人（"结果可控"）。

### 为什么职得鸭（猎聘）不像我们总弹验证？
- 【推断·最可能】走平台开放 API / 合作通道，而非浏览器模拟登录 → 没有"滑块/短信验证码"这一关。
- 【推断】即使走浏览器自动化，云端固定实例 + 养熟指纹 + 拟人节奏 + 专用出口 IP，风控信任度远高于我们本地临时起、偶尔才用的 profile。
- 我们 job-apply-agent 是"本地 CDP + 用户自己的登录态"，首次/久未操作必触发风控验证 —— 这是架构差异导致的，不是投递代码缺陷。

## 五、与 job-apply-agent 对比
| 维度 | 职得鸭 | job-apply-agent（我们） |
|------|--------|------------------------|
| 形态 | 云端 SaaS 多租户 | 本地运行（tsx + CDP） |
| 接入方式 | 开放 API + 云端浏览器池 | 本地 Chrome CDP，用户登录态 |
| 验证码 | 基本无（API/养熟指纹） | 需用户手动过滑块/短信 |
| 可控性 | 厂商托管，黑盒 | 完全可控，数据在本地 |
| 成本 | 订阅制 | 零边际成本，自托管 |
| 投递广度 | BOSS/猎聘/51job/智联 | 同 + offerbiu 邮箱直投（微信推文/官网） |
| 跟进 | 内置 AI 聊天跟进 | boss/猎聘已自动回复，其他平台未做 |
| 多版本简历 | 有（JD 定制） | 待扩展 |

## 六、关键洞察与可借鉴点
1. 接入层是胜负手：想消除验证码，最稳是对接 BOSS 开放平台 API（猎聘同理），而非苦撑本地 CDP。建议评估开放平台入驻门槛。
2. 多 Agent 编排值得借鉴：把"搜岗/匹配/沟通/投递"拆成独立 Agent（带记忆与评分），比当前单体 batch 脚本更易扩展与观测。
3. 数据底座（画像 + 匹配度 + 漏斗）是差异化卖点；我们目前只有 jobs/applications 状态表，缺"匹配度评分"与"漏斗分析"。
4. offerbiu 邮箱直投是我们独有的规模化通道（竞品未做），是差异化优势，应继续沉淀。
