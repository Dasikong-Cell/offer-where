## 零、开工前先确认：三条**改变工程量估计**的发现

本方案不是「按 offerbiu 抄一份」。核实代码后发现三件事，**直接把两个大项的代价砍掉一半**：

### 0.1 🔴 #464「简历制作」**不是从零写排版流水线**

`server/services/apply/resumeRender.ts` **已经存在**：

```ts
export function buildResumeHtml({ profile, struct, tailored }: RenderInput): string
// → 自包含 A4 HTML（内联样式、无外链），交给 cdpDriver.htmlToPdf 出 PDF
```

配套的 `tailoredResumePdf.ts` 已经跑通「HTML → 临时标签页 → PDF → `data/resume_tailored/`」全链路，
`chatResumeImage.ts` 还在复用它做「聊天框发简历图」。
而且渲染器已遵守三条硬约束（**selftest 里有 5 条断言守着**）：
信息零丢失 / 不打印内部打分 / 技能段只出现一次 / 自包含。

⇒ **缺的是「制作台 UI + 模板·配色参数」**，不是排版能力。这是 D 批能收敛的关键。

### 0.2 🔴 #463「优化历史」**已经在磁盘上，只是没人读**

`data/resume_tailored/<公司>-<职位>-<hash>.{json,html,pdf}` —— 现有 **4 条真实台账**，
`.json` 已含：

```json
{"generatedAt":"2026-09-18T18:43:21.318Z","jobId":"06426190-…","company":"严格创新",
 "position":"java开发工程师","summary":"…","highlights":[…],"orderedSkills":[…],
 "matchScore":…,"source":…}
```

「AI 匹配历史」也已落库：`jobs` 表有 `match_score` / `match_detail` 两列（前端另存了一份 localStorage，见下）。

⇒ C 批的「汇总」**不需要新建任何写入链路**，只需要补读取端。
⚠️ 但对比报告里写的「数据都在」只对**匹配**成立；**优化历史此前没有任何落库**（`/api/jobs/tailor` 与
`tailor-resume` 都只写文件、不记库）—— 这份磁盘台账是既有产物，别以为是本轮新造的。

### 0.3 🔴 「行业大类」实测 42 种取值、近义重复严重

按「token 含 `/`，且每段都不是企业性质」的口径实测（排除 `外企/合资` 这类性质 token）：

| 指标 | 实测 |
|---|---|
| 取值种类 | **42 种** |
| 覆盖 | **491 / 963 = 51.0%**（占全库 19.6%） |
| 长尾（≤2 条） | **22 种** |
| 近义重复 | `电子/通信/半导体`(164) vs `通信/电子/半导体`(39)；`房地产/建筑`(26) vs `房地产/建筑/物业`(9)；`金融/银行/保险`(16) vs `银行/金融`(7) |

⇒ 直接拿这列做筛选 = 给用户 **42 个选项、其中一半是同一个行业**，还筛不全。
**必须先做归一化映射**（42 → 约 10 个一级行业），这是 P2-c 的前置条件，不是可选项。

## 二、C 批详细方案

### C1 后端新增 `/api/stats/summary`（只回计数）

- **落点**：`server/index.ts` 挨着 `/api/stats/funnel`（约 589 行后）；`server/db.ts` 加 `countJobs()` / `countApplications()`（用 `SELECT COUNT(*)`，不要 `listJobs().length`）
- **为什么必须做**：`console.html:2309-2319` 的 `loadProfile()` 为了显示 **5 个数字**，
  分别拉了 `/api/jobs`（**2506 条**）与 `/api/applications`（全量）。这是「为了数个数把整库搬过网」。
- **验收**：合约断言 —— `loadProfile()` **函数体内**不得出现 `api('/api/jobs')`（钉函数体，不钉全文，
  其它页面仍可正当地调 `/api/jobs`）。
- 命名沿用既有 `/api/stats/*`（funnel / review / trend 已存在）

### C2 后端新增 `/api/resume/tailored-history`

- 读 `data/resume_tailored/*.json`，按 `generatedAt` 倒序，返回最近 50 条
- 每条回：`generatedAt / company / position / matchScore / hasPdf / htmlUrl`
- 🔴 **只读**：绝不删改该目录（它是 `resume_tailored` —— 任何清理档位都不碰它）
- 🔴 **路径不出后端**：只回 `basename`（如 `严格创新-java开发工程师-17ccbee1c4.html`）+ 走既有静态通道取文件，**不得回绝对路径**（路径泄露 = 本仓库 PII 红线的一部分）
- 🔴 **坏文件容错**：单个 `.json` 解析失败要 `continue`，不能让整页 500（脏数据不该让列表消失）
- **验收**：现有 4 条台账 ⇒ 返回 4 条；故意放一个坏 json ⇒ 仍返回 4 条且不报错

### C3 前端：个人中心加「历史汇总」卡（3 块）

| 块 | 数据来源 | 展示 |
|---|---|---|
| AI 匹配历史 | **后端优先**（`jobs.match_score IS NOT NULL`，按 `updated_at` 倒序）+ localStorage 补齐"粘贴 JD"那类没落库的记录 | 时间 / 公司 / 分数，点开看报告三段 |
| 简历优化历史 | C2 端点 | 时间 / 公司 / 职位 / 分数；点开看 HTML |
| 投递总结 | `/api/stats/review`（已有） | 复用复盘口径，**不在此页另算一遍** |

🔴 **不变量（最重要的一条）**：**不许再产生第二份真相源**。
现在匹配历史存在 `localStorage['ow_match_history_v1']`，页面上已如实写「保存在本机浏览器」——
但它与后端 `jobs.match_detail` 是**两份数据**。C 批要明确：**服务端为准，localStorage 只作补位**，
并在界面上区分「已入库 / 仅本机」两种来源。否则日后必然出现「同一岗位两个分数」。

### C4 顺手修（实测到的两处小问题）

1. `loadProfile()` 的两条全量拉取（见 C1）—— 一并去掉
2. `#pfStats` 里 `p.updatedAt` 文案是「最近更新」，实际是**档案更新时间** ⇒ 改成「档案更新」，
   否则会被读成「数据更新时间」

## 三、D 批详细方案（简历制作整页）

### D1 后端：把样式抽成**主题参数**（扩展，不是重写）

```ts
export interface RenderTheme {
  template: 'classic' | 'modern' | 'compact' | 'elegant';
  accent: string;        // 主色（分节线 / 标题色）
  fontScale: number;     // 0.9 ~ 1.15
  showPhoto?: boolean;
}
export function buildResumeHtml(input: RenderInput & { theme?: RenderTheme }): string
```

- 🔴 **主题是数据、不是 if/else 分支树**：模板差异集中在一张 `THEMES` 表里（间距 / 分节样式 / 是否双栏），
  别写 4 套 `if (theme === 'modern') { … }`
- 🔴 **默认参数必须等于现在的样式** ⇒ 既定「一岗一简历」的产物**字节不变**（这是回归底线）
- **验收**：selftest 里那 5 条（信息零丢失 / 不打印内部打分 / 技能只出现一次 / 自包含 / 重排技能）
  **改动前后都要绿**；另加一条：同一份输入 + 不同 accent ⇒ 产物只在颜色处不同

### D2 后端：制作台草稿存储（**用 `app_kv`，不建新表**）

- 前缀 `resumedoc:<id>`，复用已有 `kvKeysByPrefix()`（`server/db.ts:437`）⇒ **零迁移**
- 结构：
  ```ts
  interface ResumeDoc {
    id: string; title: string; theme: RenderTheme;
    sections: Array<{ key: string; title: string; lines: string[] }>;
    updatedAt: string;
  }
  ```
- 端点：`GET /api/resume/docs`（列表）/ `GET|PUT|DELETE /api/resume/docs/:id`
- 🔴 **不变量**：草稿与「简历版本」（`/api/resume/version` 的 原始/优化）是**两回事**，
  用独立前缀、**不覆盖** `resume/原始|优化` 那两个文件。同一份数据不留两个可编辑入口（本仓库既有纪律）。

### D3 前端：`#view-resumemake` 替换占位（`console.html:1208-1223`）

三栏布局：

```
[左：分块编辑]            [中：实时预览]         [右：模板 / 配色 / 字号]
 基本信息 / 求职意向        自包含 HTML 渲染       4 套模板 · 4 种配色
 教育 / 实习 / 项目         （直接复用 D1 产物）   字号滑块
 校园 / 荣誉 / 技能                                [下载 HTML] [生成 PDF]
 自我评价                                          [存为草稿]
 [+ 添加一段 X 经历]
```

- 🔴 **「添加一段 X 经历」必须真写草稿**，不许是假控件（本页上一版的诚实占位就是靠"不放按钮"做到的，
  这次一旦放按钮就必须能用）
- 🔴 **导出分两级，不混为一谈**：
  - **「下载 HTML」永远可用**（纯前端 Blob，无依赖）
  - **「生成 PDF」依赖调试 Chrome 的 CDP**（`htmlToPdf` 需要已连接的浏览器）⇒
    未连接时**按钮置灰 + 写明原因 + 给出"怎么连"的入口** —— 直接复用 A 批那套护栏模式
    （判据唯一化 + 禁用 + 说明 + 上架入口），**不要**留一个点了没反应的下载按钮
- 函数一律**顶层声明**（`extractFn` 才抠得出来做单测）

### D4 与既有流水线打通（复用，不另起一套）

- 「用这份草稿生成一岗一简历」⇒ 把 `sections` 拍平成 `struct.rawText`（复用 `splitResumeBlocks` 的格式约定），
  喂给既有 `tailorResume()` + `buildResumeHtml()` ⇒ 出 PDF。**不新写第二个渲染器**
- 相反方向：`/api/resume/version` 的原始稿解析结果 ⇒ 一键导入成草稿分块（省手工录入）

### D5 验收（D 批）

- **行为级单测**（抠函数进 `vm` 沙箱）：
  - 换 `accent` ⇒ 产物里的颜色跟着变（不是断言"代码里有个变量"）
  - `sections` 顺序 = 渲染出的分块顺序（不是原文出现顺序）
  - 草稿读取失败 ⇒ **拒绝保存**（浅合并会抹平整份草稿，见本仓库既有纪律）
- **E2E 真点击**：改一个字段 → 预览立刻变 → 下载 HTML → 文件里含那个字段
- **破坏性对照**（≥4 个变异体，每个证明一条断言有区分力）：
  ① 样式写死（忽略 `accent`）；② 草稿写入覆盖了「简历版本」文件；
  ③ 导出按钮是假的（点了不产出）；④ 改字段但预览不刷新

## 踩到的坑（已写进记忆与 skill）

1. **jobs 加列是五处同步**，第 5 处是 `updateJob` 那份硬编码的 `Partial<Pick<JobRow, ...>>`。
   漏它 ⇒ `tsc -b` 报 TS2353，且 `tsc --noEmit -p tsconfig.json` 会先过一遍（差点误判成缓存问题）。
2. **跨行断言 needle 写死 `\n` 在 CRLF 文件上静默不匹配**。
3. **对照脚本解析红行要剥 `  — 备注`**，否则有备注的断言全被误判成「该红没红」。
4. **两条断言共用同一 needle 就不独立**（对照跑出「有误伤」才发现）。

## 三条设计约束

1. **不动 `buildResumeHtml()`** —— 一岗一简历的既有产物必须字节不变；新链路另写 `renderResumeDoc()`。

## 探针跑出来的真 bug

`const id = safeDocId(req.body?.id) || ('d' + Date.now().toString(36))`
—— `safeDocId` 空输入返回 `'doc'`、**永不为假** ⇒ 兜底分支永远走不到 ⇒ 每份草稿 id 恒为 `doc`
⇒ **建第二份必然 409**。已改「先判空再规整」，并加静态断言 + 变异体 D14 钉住。

## 踩到的坑

1. **变异体无效**：在路由行尾加注释不改变 needle ⇒ 报「该红没红」（是变异体写错，不是断言失效）。
2. **纵深防御的期望要分开写**：破第一道防线时第二道还在 ⇒ 那条断言**应该保持绿**；
   每道防线各配一条断言 + 一个变异体。
3. **共享 `_repro` 库第三次中招**：E2E 的「统计卡计数」是全库计数 ⇒ 上一轮残留投递记录让它多算 1。
   已给 E2E 加「开跑先清 `__E2E_` 开头的投递记录」。
4. Playwright 默认自动取消 `prompt`/`confirm`；常驻 `page.on('dialog')` 与后面的 `page.once` 冲突
   （直接用 `once`，每个对话框单独注册）。
5. 空列表时下拉的占位 option 会让「数 option 总数」恒为 1 ⇒ 只数有值的选项。
